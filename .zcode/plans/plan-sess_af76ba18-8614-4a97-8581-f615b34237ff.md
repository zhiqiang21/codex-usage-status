# Library 存储扩展：评审后修订方案

## 安全边界

- 保留 Caches、Application Support、/private/tmp 的大小展示。
- Application Support 全部只读：LaunchServices 查询不到不等于卸载，卸载也不等于支持数据不再需要。不得生成删除 action 或加入批量选择。
- Caches 仅允许 bundle ID 可由 LaunchServices 解析为实际存在的应用包、且进程列表中没有该包内可执行文件的目录。未知归属保持只读，不根据 bundle ID 末段猜测可执行名。进程查询失败保持只读。
- tmp 仅允许当前用户拥有且整棵树所有普通文件和目录均超过 3 天未修改的目标；符号链接、特殊文件、其他所有者、组或其他用户可写的目录、挂载点、读取不完整均拒绝。年龄不代表未使用，UI 不再使用“可安全删除”或“未使用”的承诺。
- libraryDirectory action 的类别白名单仅包含 userCaches、systemTmp，服务层与模型均校验，禁止借此绕过 Codex 或模拟器保护。
- 保留整树身份复核、精确清单确认、lsof 检查、串行批量和不重试。占用检查是瞬时观察，不能保证应用之后不会启动或重新打开文件。现有基于路径的删除仍存在最终复核后的竞态，不宣称原子删除或对抗同用户恶意进程；共享可写的 tmp 子树保持只读。后续若要求对抗此类进程，应单独实现基于目录描述符的隔离/删除协议。

## 实现

1. StorageAppResolver 提供 bundle ID → 全部已注册 URL 查询，并验证实际包的标识，只用于确认缓存归属或显示已安装提示；删除可执行名猜测工具。
2. Service 扫描先判定应用归属/运行状态，再决定是否保存 manifest；Application Support 和不可清理缓存不保留完整节点清单。缓存与 tmp 根据完整 manifest 检查所有后代的所有者、类型和目录权限；tmp 额外检查所有后代年龄。
3. 删除时重复相同业务规则，tmp 不运行 ps。单项 Library 清理不再为计算变化量额外扫描一次整个根目录；仍在删除后扫描更新 UI，整个类别变化量返回未知。
4. Models/UI：Application Support 无批量选择；候选标记改为“符合清理条件”，确认中说明缓存可能重建、数据不可恢复、时间判断不保证未使用。
5. 测试覆盖 Chrome 包内进程（含辅助进程）、相同 bundle ID 的多个安装副本和包标识不匹配、未知归属、Application Support 只读、tmp 新子文件/所有者/类型/权限、错误 action、越界路径、扫描后变化，以及 tmp 无 ps 和只读条目无 manifest。
6. 同步中英文 README，明确以上规则及瞬时检查的限制。

## 验证

使用临时 home/tmp、注入 resolver 与命令替身，不删除真实系统目录。运行存储 Service/Store 的测试，再按失败情况扩大范围。检查 git diff --check。不提交、不发布。

## 实际验证结果

- 2026-11-08：DeveloperStorageTests 39 项与 DeveloperStorageStoreTests 10 项，共 49 项全部通过，包含新旧类别混合批量清理。
- 精确三天边界使用整秒时间，避免文件系统时间精度截断影响测试口径。
- git diff --check 通过；未修改真实用户缓存、支持数据、临时目录条目或设备数据。
- 未进行大型真实目录性能测量或手工 UI 验证；原子删除与同用户恶意并发进程防御不在本次保证范围内。

## 删除性能优化

- UI 实际调用 cleanBatch；将 Library 类别不做删除前全目录扫描的规则同步到批量入口。保留操作后快照和同卷一次空间测量，类别占用减少量明确显示无法测量。
- 其他类别删除前只做容量测量，不保存节点清单、不调用 simctl/ps；批量按类别共享。
- 安全复核改为按排序遍历逐节点比较已有清单，首个变化立即拒绝；仍核对完整节点数量、身份、挂载点与硬链接去重后的分配空间。
- 去掉批量每项进入安全复核之前的重复路径/进程校验；lsof 前后两次实时复核均保留。
- 不可变 manifest 的安全形状属性只在初始化计算一次，避免 MainActor 上每次 canClean 再遍历整树。
- tmp 顶层已不符合条件时只统计后代大小、不保存后代身份；其余最终只读的 Library 条目也不常驻 manifest。
- 增加进程查询次数、硬链接统计、缺失/多余节点和错误空间元数据的回归测试，并用独立临时目录进行优化前后同规模对照；不使用真实用户数据。

### 性能验证结果（2026-11-08）

- 最终 DeveloperStorageTests 41 项、DeveloperStorageStoreTests 10 项、StorageCleanupSafetyTests 12 项，共 63 项通过；git diff --check 通过。
- Swift 6、-O 独立驱动，使用本次优化前的源码副本与最终源码，调用 cleanBatch；每次生成独立临时根目录，目标 1,500 个旧普通文件，无关目录 4,500 个近期普通文件。仅计清理耗时，不含建树和初次扫描；lsof 用空占用命令替身，两版本各运行 3 次。
- 优化前：0.573、0.541、0.495 秒，中位 0.541 秒；优化后：0.303、0.294、0.323 秒，中位 0.303 秒，约减少 44%。
- 该对照仅说明此本地工作负载的遍历/删除开销变化，未测真实 lsof、simctl、UI 延迟、内存峰值或实际大型用户目录，不能外推为所有清理都提速 44%。

## 系统访问权限与真实路径修复

- 从 NSError 的 POSIX EACCES/EPERM、Cocoa 无权限代码及 underlying error 收集 permissionDeniedPaths，保持原有详细诊断，不通过本地化文本判断权限。
- Store 单独跟踪最新扫描的权限失败类别，避免保留旧快照时丢失授权引导。显式重扫仅针对这些类别，成功后移除引导。
- 界面只在真实权限失败时显示系统设置入口、当前 app 的 Finder 定位及重新扫描按钮；不自动弹窗、不存储“假定已授权”的布尔值。完整磁盘访问必须由用户在系统设置开启，由系统保存；可能需要重启应用，BSD/ACL/其他系统保护仍可能拒绝访问。
- 本机复现 Foundation 的 resolvingSymlinksInPath 与 standardizedFileURL 将 /private/tmp 解析为 /tmp、将 /private/var 路径改写为 /var 的行为；保留 URL 输入路径拼写，不再用 Foundation 标准化改写安全边界；统一通过 POSIX realpath 生成及核对删除证据的真实路径。进程快照允许退出进程保留原始绝对路径用于保守匹配，删除路径解析失败保持拒绝。
- 测试夹具同样以 POSIX 真实路径创建；新增 /private/tmp 下独立测试根的扫描/删除、真实符号链接根拒绝、权限分类、根/后代权限失败及旧快照授权引导回归测试。绝不扫描后删除真实 /private/tmp 条目。
- 系统设置授权及 TCC 持久化需要在实际签名 app 上手工验证，自动测试不修改系统隐私设置。

### 权限改动验证结果

- 2026-11-08：DeveloperStorageTests 44 项、DeveloperStorageStoreTests 11 项、StorageCleanupSafetyTests 12 项，共 67 项通过；git diff --check 通过。
- 本机实测 Foundation standardizedFileURL 会把 /private/tmp 改写为 /tmp，resolvingSymlinksInPath/standardization 也会将 /private/var 路径改写为 /var；POSIX realpath 保留真实 /private 路径。初版仅替换解析函数仍被 URL 标准化影响，最终同时移除安全路径的 Foundation 标准化，保留严格路径相等验证。
- 回归测试在 /private/tmp 下独立创建/移除自己的测试目录，未扫描后删除共享目录中的真实条目；未操作系统隐私设置。
